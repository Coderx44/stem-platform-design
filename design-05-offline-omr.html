Conflict Resolution Strategy

Why Conflicts Are Rare
- Trainers only edit their own attendance/data
- Offline window is hours, not days
- No two trainers edit the same student's attendance
- Session attendance is per-trainer scope
When Conflicts Occur
- PM edits an entry while trainer is offline editing same
- Strategy: Last-write-wins with notification
- Server version wins; trainer gets notified of conflict
- Conflict log stored for manual review
Sync Queue Record:
{ id, entity_type, entity_id, operation (create/update), payload, local_timestamp, synced: false, retry_count, conflict_status }

OMR Processing Pipeline

OMR Scan → Score Flow
1. Capture
Trainer photographs OMR sheet via mobile camera
OFFLINE OK
2. Upload
Image queued locally, uploaded to S3 when online
NEEDS SYNC
3. Queue
Backend receives upload, creates processing job in Redis queue
ASYNC
4. Process
OMR worker reads image, detects bubbles, extracts answers
WORKER
5. Score
Compare answers vs template answer key, compute scores
AUTO
6. Result
Scores saved, linked to student, trainer notified
COMPLETE
── OMR Processing Detail ──
Assessment Template
Created by Admin:
- Name, grade, subject
- Number of questions
- Answer key (array)
- Subject/skill mapping per Q
- Scoring rubric (marks per Q)
- OMR layout config
Image Processing
OMR Worker pipeline:
1. Download image from S3
2. Perspective correction
3. Detect registration marks
4. Identify bubble grid
5. Threshold + detect filled bubbles
6. Map to answer array
7. Confidence score per answer
Error Handling
When processing fails:
- Low confidence → flag for manual review
- Unreadable image → notify trainer to re-scan
- Partial read → save what's readable, flag rest
- Retry up to 3 times
- Manual override always available
- All results reviewable before finalization

OMR Processing — Technology Options

Option A: OpenCV + Custom Pipeline
Use opencv-js or Python OpenCV worker.
Full control over processing pipeline.
Well-documented for OMR use cases.

Pro

  • No external dependency
  • Customizable per template

Con

  • More development effort
  • Need to handle edge cases
Option B: OMRChecker (Open Source)
Open-source OMR processing library.
Wrap as a microservice/worker.
Battle-tested for education use cases.

Pro

  • Faster to ship
  • Education-focused

Con

  • Python dependency
  • May need customization
Recommendation: Start with Option B (OMRChecker) wrapped as a Python microservice behind the Redis job queue. It's purpose-built for education OMR sheets and will get you to production faster. Migrate to a custom pipeline only if OMRChecker can't handle your specific template formats.
