1. Extract tenant_id from JWT claims

3. Match requested route → module_key
4. If module not licensed → 403 Module Not Available

Licensing Data Model

── tenants ──
  id, name, slug, plan_tier, status, created_at
── modules ──
  id, key (e.g. "school", "attendance"), name, description, version
── tenant_modules ──
  tenant_id, module_id, enabled, licensed_until, max_users, config_overrides (JSONB)
── plan_templates ──
  id, name (e.g. "Basic", "Pro", "Enterprise"), included_modules[], max_users, price
How licensing works: When a new tenant signs up, a plan template pre-populates their tenant_modules entries. Admins can override individual modules (enable/disable, extend license, adjust user limits). The config_overrides JSONB field allows per-tenant customization (e.g., custom activity types for non-session attendance).
