Why This Approach

Custom Backend
Full control over business logic. OMR processing, workflow engine, and reporting need real compute — not Edge Function constraints. Clean module boundaries with standard TypeScript.
Supabase (Auth + DB)
Handles identity (JWT, OTP, SSO) and PostgreSQL with RLS for tenant isolation. Managed service — no DB ops overhead. Can migrate off independently if needed.
AWS S3 (Storage)
All media — OMR sheets, session photos, documents, exports. Presigned URLs for direct upload/download. Scalable and cheap.

Pros

  • Full control over business logic + clean module boundaries
  • Supabase handles what it's best at (auth, JWT, RLS, PostgreSQL)
  • S3 gives scalable, cheap storage with presigned URLs
  • OMR processing runs in proper compute (no function limits)
  • Fully testable — standard TypeScript, standard test frameworks
  • Can migrate off Supabase or S3 independently if needed
  • Team writes TypeScript everywhere

Cons

  • More infrastructure than pure Supabase (need to host backend)
  • Two auth integration points (Supabase JWT validated in backend)
  • Slightly more initial setup

Why Not the Alternatives

Pure Modular Monolith (no Supabase)
Would need to self-manage auth, database hosting, and connection pooling. More infrastructure burden for no added benefit. Supabase gives us managed auth + Postgres for free.
Supabase-Native + Edge Functions
Edge Functions have cold-start latency and execution limits. OMR processing and complex workflow logic can't run there — you'd need a separate service anyway, defeating the purpose. Hard to maintain modular boundaries.
